# Работа K2-01

- Код студента: Соня
- Что сделано: проверены образ и контейнеры стенда, остановлен и снова запущен сервис `web`.

## Команды

```text
docker image inspect devops-course:base
docker compose ps
docker compose stop web
curl -i http://127.0.0.1:8080/
docker compose start web
docker compose ps
```

## Наблюдения

- Образ `devops-course:base` имеет идентификатор `sha256:ceaed494...`, платформу Linux/amd64, команду `python app.py` и документированный порт `8000/tcp`.
- Из образа были созданы два контейнера: `api` и `web`. У `api` роль API и внутренний порт 8000; у `web` роль веб-части и опубликованный адрес `127.0.0.1:8080`.
- После `docker compose stop web` контейнер `web` получил статус `Exited (137)`, а `api` продолжил работу в статусе `healthy`.
- Запрос к `127.0.0.1:8080` после остановки web завершился ошибкой подключения.
- После `docker compose start web` оба сервиса стали `healthy`.
- После восстановления создана заявка №3 с видом `battery`.

## Вывод

Остановка `web` делает страницу недоступной пользователю, но не останавливает независимый контейнер `api`. Повторный запуск web восстановил доступ к приложению и отправку заявок.

## Ответ на вопрос из задания

Нет. Остановка `web` завершает контейнер, но образ `devops-course:base` остаётся в Docker и может использоваться для повторного запуска контейнера.
