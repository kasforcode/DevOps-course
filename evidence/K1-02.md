# Работа K1-02

- Код студента: Соня
- Что сделано: запущен учебный стенд и выполнена диагностика API через сервис `tools`.

## Команды

```text
docker compose up -d
docker compose ps
docker compose run --rm tools sh
pwd
ls
ps -ef
ss -lnt
curl -i http://127.0.0.1:8000/health
exit
docker compose logs --tail=20 api
```

## Наблюдения

- `docker compose ps` показал контейнеры `api` и `web` из образа `devops-course:base`. API имел статус `healthy`.
- Внутри `tools` команда `pwd` вернула `/`, а `ls` показала стандартные каталоги Linux-контейнера.
- `ps -ef` показала процесс `python app.py` с PID `1`. Это основной процесс сервиса API.
- `ss -lnt` показала слушающий сокет `0.0.0.0:8000`.
- `curl -i http://127.0.0.1:8000/health` вернула `HTTP/1.0 200 OK` и тело:

```json
{"process": "running", "role": "api"}
```

- В логах API есть строка запуска с `"event": "started"`, `"role": "api"`, `"port": 8000`, а также строки HTTP-проверок `/health` со статусом `200`.

## Вывод

Процесс `python app.py` обслуживает API внутри контейнера и принимает соединения на порту `8000`. Ответ `/health` с кодом 200 подтверждает, что этот процесс отвечает на HTTP-запросы.

Сервис `tools` видит процессы API, потому что в Compose он использует PID namespace сервиса `api` (`pid: service:api`). Это пространство процессов контейнера API, а не процессы всего компьютера.

## Ответ на вопрос из задания

`tools` видит процессы `api`, а не все процессы компьютера, потому что ему предоставлено пространство процессов контейнера API. Контейнеры изолированы от процессов хоста.
