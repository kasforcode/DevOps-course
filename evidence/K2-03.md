- Что сделано: приложение запущено на образе `devops-student:v1`, проверена сохранность заявок после пересоздания API.

## Команды

```text
docker compose stop
docker compose -f compose.student.yaml config
docker compose -f compose.student.yaml up -d
docker compose -f compose.student.yaml up -d --no-deps --force-recreate api
docker compose -f compose.student.yaml ps
```

## Наблюдения

- `compose.student.yaml` успешно прошёл `config` и использует `devops-student:v1` для `api` и `web`.
- После запуска оба сервиса получили статус `healthy`.
- Создана заявка №4 с видом `screen`.
- До пересоздания идентификатор API был `33281bbc7659...`, после `--force-recreate` стал `206e4e940f40...`.
- После пересоздания список заявок сохранил заявку №4. Затем создана новая заявка №5 с видом `battery`.

## Настройки и запуск

`API_URL=http://api:8000` сообщает web адрес API во внутренней сети Compose. Имя `api` разрешается внутри этой сети в контейнер API. Порт `8000` используется между контейнерами; порт `8080` опубликован только для браузера на компьютере через `127.0.0.1:8080`.

Том `requests` подключён к `/data` у API. В нём хранится база заявок, поэтому данные не пропали после замены контейнера API.

Для запуска используйте:

```text
docker compose -f compose.student.yaml up -d
```

## Ответ на вопрос из задания

Если хранить базу только в изменяемом слое контейнера, она будет потеряна при пересоздании контейнера. Named volume существует отдельно от контейнера и сохраняет данные.
