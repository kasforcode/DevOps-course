# K3-03. Тестовый барьер

Команда шага:

```text
python -m unittest discover -s tests -p test_app.py -v
```

Успешный запуск с реальными тестами до ошибочного эксперимента: https://github.com/kasforcode/DevOps-course/actions/runs/44523250518

- событие: `push`;
- SHA: `c5a9e39896ce6b42bcf2aa74ed7200b948174605`;
- результат: `success`.

Ошибочный запуск: https://github.com/kasforcode/DevOps-course/actions/runs/44523513065

- событие: `push`;
- SHA: `24dae22d24085118d80585e5d4e87190fe1c70ef`;
- результат: `failure`;
- причина: в `test_create_request` ожидался HTTP `200`, а приложение возвращает
  корректный для создания заявки статус `201`; поэтому assertion не выполнился.

Исправленный запуск: https://github.com/kasforcode/DevOps-course/actions/runs/44523694558

- событие: `push`;
- SHA: `6c39a76060cc4821a1f3ad648e380cd71d663e54`;
- результат: `success`.

В итоговой версии `tests/test_app.py` снова ожидает `201`. Неверное ожидание делает CI
красным, потому что команда unittest завершается с ненулевым кодом выхода при assertion
failure; это показывает, что проверяется контракт приложения, а не скрывается ошибка.
